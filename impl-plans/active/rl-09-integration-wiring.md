## Intent and Context

This plan connects the finished pieces:

- a production `RateLimitUsageService` factory;
- one shared service per process, passed to `MachineDashboardRouter` in
  `serve`, in the desktop window, and in the menu-bar app;
- the menu-bar hook-in: the Pie charts submenu, polling only when a
  rate-limit pie is selected, the multi-pie glyph, and the dropdown rows;
- an end-to-end non-disclosure test;
- regeneration of the tracked dashboard assets;
- the full verification gate.

### RateLimitUsageProduction.swift

`extension RateLimitUsageService { public static func production(environment: [String: String] = ProcessInfo.processInfo.environment) -> RateLimitUsageService }`
composes these pieces:

- `ClaudeRateLimitFetcher(credentials: ClaudeCredentialProvider(environment:), transport: URLSessionRateLimitTransport())`;
- `CodexRateLimitFetcher(credentials: CodexCredentialProvider(environment:), transport: same)`;
- `codexFallback: CodexRateLimitSessionFallback(sessionsRoot: CodexHome.url(environment:).appendingPathComponent("sessions", isDirectory: true))`.

It uses the default 60s interval. Construction performs no I/O.

### MenuBarApp.swift and MenuBarApp+PieCharts.swift

- **Service.** Add `private let rateLimitService = RateLimitUsageService.production()`
  (or a lazily created equivalent) and `var latestRateLimits: RateLimitsResponse?`.
  Pass the service to the `MachineDashboardRouter` near line 256, so the
  dashboard and the menu bar share one throttle.
- **Selection.** The selection is
  `currentState?.menuBarPieCharts ?? PieChartSelection.defaultSelection`.
- **Polling (PR-M2).** Add a helper `refreshRateLimitsIfNeeded() async` in
  `MenuBarApp+PieCharts.swift`.
  - It reads the selection from `currentState`, falling back to
    `PieChartSelection.defaultSelection`.
  - It calls `await rateLimitService.current()` only when the selection
    contains a non-budget chart. Otherwise it returns immediately, with no
    network or Keychain access; this is the default.
  - It stores the result in `latestRateLimits` and then calls
    `updateStatusIcon()`, so the glyph redraws as soon as the data arrives.
    The `appliedIconState` dedup prevents flicker.
  - It must run on every `refresh()` call, whatever the snapshot path does.
    `refresh()` (`MenuBarApp.swift:329-357`) has an early return at :331-334
    when there is no `machineSnapshotStore`, and early returns at :341-342
    when the snapshot is nil or the generation changed.
  - Implementation choice: wrap the existing body so that the helper always
    runs. Either call it at the top of `refresh()` before the existing guard
    (it reads `currentState`, which `mutateState` and bootstrap already set),
    or move the existing body into a private `refreshSnapshot()` and have
    `refresh()` call `await refreshSnapshot()` and then
    `await refreshRateLimitsIfNeeded()`.
  - Do not alter the snapshot logic, the generation guard, or the
    status-title semantics.
- **Settings submenu.** Add
  `PieChartMenu.item(selection:target:action:)` to `settingsItem()`.
  - The action handler `togglePieChart(_ sender: NSMenuItem)` reads
    `representedObject` as `PieChartID(rawValue:)`.
  - It persists through the existing
    `mutateState { $0.menuBarPieCharts = PieChartSelection.toggled(id, in: $0.menuBarPieCharts) }`,
    then calls `updateStatusIcon()`.
  - Do NOT add another `Task { await refresh() }`. `mutateState` already
    schedules one (`MenuBarApp.swift:576`,
    `if snapshotService != nil { Task { await refresh() } }`), and through
    the polling helper that refresh fetches the newly selected rate-limit
    data and redraws the glyph.
- **Glyph.** Replace `StatusIconState` with the comparable
  `[MenuBarPieEntry]` (plus the accessibility text), keeping the
  `appliedIconState` dedup so the icon does not flicker. Build the image
  with `MenuBarPieStrip.image(entries:accessibilityDescription:)`.
  - The budget entry carries today's values: `fraction`, `hasBudget`, and
    `warning`.
  - Each rate-limit entry gets its fraction from
    `RateLimitDisplayFormatting.pieFraction(entry(for:in:).window)`.
- **Dropdown.** In `populateMenu`:
  - keep the existing budget block only when `budget` is selected. The error
    details item must still be shown when present;
  - after it, append `RateLimitMenuView.items(selection:response:now:)`.
- **Line budget.** Put the new methods in `MenuBarApp+PieCharts.swift`. Relax
  `private` to internal only on the members that file needs. Do not
  restructure anything else. `wc -l MenuBarApp.swift` must stay below 1000.

- Compose the real `ClaudeRateLimitFetcher` and `CodexRateLimitFetcher` with
  fake credential providers that return the sentinels

Assertions:

- The body contains none of the three sentinels.
- Claude `fiveHour.remainingPercent == 100` and
  `weekly.remainingPercent == 47`.
- Codex `weekly.usedPercent == 82` and `fiveHour == null`.
- The transport saw exactly two URLs, and none contains `token` or
  `refresh`.
- `RateLimitUsageService.production(environment: ["HOME": <temp dir>])`
  constructs without I/O and without throwing. Do not call `current()` on
  it; that would reach the network.

## Key Pitfalls

- `refresh()` has early returns at `MenuBarApp.swift:331-334` and :341-342.
  Rate-limit fetching must not depend on them. If the fetch is placed after
  the snapshot work, a nil budget snapshot means rate-limit pies never fill.
  If `updateStatusIcon()` is missing after `latestRateLimits` is stored, the
  glyph lags one poll interval (default 20 s).
- Never call `current()` on a production service in tests. Tests must not
  touch the network.
- Default behavior with selection `[budget]`:
  - the glyph is the same image as today;
  - no `current()` call is made;
  - the dropdown is unchanged.
- `MenuBarApp` is `@MainActor`. `await rateLimitService.current()` hops to
  the actor, so do not block the main thread.
- `mise run build` regenerates hashed files in `Sources/AppCore/Resources/Web`.
  Old hashed assets are deleted by `scripts/sync-frontend-assets.sh`. Commit
  the resulting state as is; do not hand-edit it.
- Run the manual smoke test only with output filtered so that no secrets are
  printed. Use the `grep -c` approach in verification step 9; never `cat`
  credential files.
